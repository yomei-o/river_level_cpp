# river_level_cpp — 川の水面を映像の y 座標で測る

ライブカメラの映像から、護岸と水の境目（水面）の **y 座標**を、7 通りの方法で求める C++ です。
ネイティブ（Windows）と WebAssembly（ブラウザのデモ）の両方で動き、どちらも同じ値を出します。

**デモ**: https://yomei-o.github.io/river_level_cpp/ （善福寺川・石神井川の 60 秒の録画入り）

## 方法

| | 方法 | 何を見るか | 善福寺川 | 石神井川 |
|---|---|---|---|---|
| A | 横エッジ | 上下 h 行の明るさの差が最大の行（短冊ごと、中央値） | 397 | 486.5 |
| B | 明るさ 2 段近似 | 行平均を「明るい上／暗い下」の 2 段で近似したときの分け目 | 389 | 486.5 |
| C | 鏡映対称 | 上下が鏡写しになる行（正規化相関） | ✕ 466 | ✕ 451 |
| D | 水際のちらつき | 直近 T フレームで最も揺れる行 | △ 412 | ✕ 564 |
| E | 直線当てはめ | 列ごとの段差点に RANSAC で直線 y=ax+b（傾きも出る） | 399.7 | 485.6 |
| F | 水位標の下端 | 水位標の列の色 R−B が暖色から青に変わる行 | 400 | ✕ 415 |
| G | 色 2 段近似 | 護岸全体の R−B を「暖色の上／青い下」で近似 | 392 | ✕ 409 |

値は 60 秒（3 フレームおき、600 フレーム）の中央値です。座標は 1280×720 に揃えた画面での値です。
目で見た水面は、善福寺川が y≈398〜400、石神井川が水位標の位置で y≈486 です。

- **使えるもの**: A と E は両方の川で合いました。E は線の傾きまで出ます
  （石神井川は左 y≈473 から右 y≈500 へ傾いています）。B は、水際の濡れて暗い石の段のぶん、少し上に出ます。
- **C（鏡映）が合わない理由**: どちらの川も浅くて水が澄んでいるので、水面の下に見えるのは映り込みではありません。
  水を通して見えている本物の護岸です。そのため、水面を境にした上下の鏡対称は成り立ちません。
- **D（ちらつき）**: 穏やかな日は水面がほとんど動かないので、手がかりが弱いです。
- **F・G（色）**: 澄んだ水は空を映して青く（B>R）、護岸は暖色（R>B）です。善福寺川ではこれが効きます。
  石神井川は水が茶色く濁っていて R>B なので、効きません。F は、水位標の目盛りの青い区間を水面と間違えます。

### 夕方・夜（2026-11-10）

同じカメラを夕方（16:35）と夜（16:55、真っ暗）にも 1 分ずつ録画して、Python 版で測りました（15 フレームおき）。

| | 方法 | 昼 | 夕方 | 夜 |
|---|---|---|---|---|
| 善福寺川 | A 横エッジ | 397 | 396 | 394 |
| | E 直線当てはめ | 399.7 | 399.4 | 399.0 |
| | F 水位標（色） | 400 | 402 | 426（ずれた） |
| 石神井川 | A 横エッジ | 486.5 | 486.5 | 486.5 |
| | E 直線当てはめ | 485.6 | 487.2 | 487.4 |

カメラの感度が高く、夜もカラーで写っていました。明るさの段差だけを見る A と E は、夜も昼と 1〜3px の差に収まっています。
色を使う F（水位標の R−B）は、暗いと 26px ずれました。夜に使うなら A か E です。

## ビルド（ネイティブ）

mp4 の展開・RGB 変換・書き出しには [mediakit_cpp](https://github.com/yomei-o/mediakit_cpp) を使います。
隣のフォルダ（`../mediakit_cpp`）に clone してあればそれを、無ければ CMake が GitHub から取ってきます。

```sh
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release --target river_level
```

```sh
river_level zenpukuji_60s.mp4 --every 3 --overlay out.mp4 --snap out.bmp
river_level shakujii_60s.mp4  --every 3 --roi 120 410 1160 590 --gauge 685 694
```

| オプション | 意味 | 既定 |
|---|---|---|
| `--roi x0 y0 x1 y1` | 解析する範囲 | 300 300 1150 520（善福寺川） |
| `--gauge gx0 gx1` | 水位標の列（方法 F） | 621 630 |
| `--csv f` | フレームごとの全方法の値 | levels.csv |
| `--overlay f.mp4` | 線を重ねた動画 | なし |
| `--snap f.bmp` | 線を重ねた 1 枚 | なし |
| `--every N` / `--max N` | N フレームおき / 最大 N フレーム | 1 / 全部 |
| `--strip` `--edge-h` `--mirror-k` `--temporal-t` | 短冊の幅、段差の高さ h、鏡映の K、時間窓 T | 85 4 20 30 |

ライブ配信は、まず `record.py` で mp4 に録ってから解析します（yt-dlp と ffmpeg を使います）。

```sh
python record.py "https://www.youtube.com/watch?v=u6l1L08s-MQ" zenpukuji_60s.mp4 60
```

## Python 版

`python/river_level.py` は C++ 版と同じ 7 つの方法・同じオプション・同じ CSV です（numpy と PyAV が必要）。

```sh
python python/river_level.py shakujii_60s.mp4 --every 3 --roi 120 410 1160 590 --gauge 685 694
```

計算は C++ と同じ順序・同じ式です。同じ画素を入れれば、CSV は全フレーム・全項目で完全に一致します。
確認には、生の RGB24（1280×720 を並べただけ、拡張子 `.rgb`）を両方に入れて比べました（善福寺川・石神井川の 60 フレームずつ）。
RANSAC の乱数も、そのために両方とも自前の xorshift32 にしてあります。

mp4 から直接読むと、値が少しずれることがあります（例: 善福寺川の G が 392 と 394）。
これは計算の違いではなく、mp4 の展開の違いです。C++ は mediakit_cpp、Python は PyAV で展開していて、
YUV→RGB 変換の画素がわずかに違います。

## ビルド（WASM デモ）

```sh
./build_wasm.sh        # docs/river_level.js と .wasm ができる（EMSDK で emsdk の場所を指定）
```

`docs/index.html` は、動画を `<video>` で再生して、canvas の RGBA を WASM に渡します。
ローカルの動画ファイルを開くことも、YouTube のタブを画面共有で取り込んでライブのまま解析することもできます。

## ファイル

- `python/river_level.py` — Python 版（C++ と同じ値）
